# Architecture

The React client authenticates with Supabase. FastAPI validates bearer tokens with Supabase Auth before querying user-owned rows. The official Codeforces API supplies `user.info`, `user.status`, `user.rating`, and `problemset.problems`; FastAPI stores their public data in PostgreSQL. The dashboard, verified roadmap, and recommendations read that stored history. `shared/openapi.json` and `frontend/src/generated/api.ts` are generated with `make contract`.

`codeforces_users` stores the handle, profile and import cursor. `codeforces_submissions` is keyed by handle plus official submission ID. `codeforces_problems` is keyed by contest ID plus index. Accepted problems are distinct by that problem identity and require verdict `OK`. Repeated accepted submissions do not increase solve totals. Contest rating events are stored separately in `codeforces_rating_changes`; ratings are never inferred from problem difficulty.

`linked_platform_accounts` associates a public handle with a verified Supabase user ID and tracks sync status and last successful time. `roadmap_challenges` stores one stable assignment per user, topic and tier. Assignments refer to official catalog rows. Verification and completion are computed from accepted submissions for the linked handle. The 38-topic prerequisite graph is validated for cycles at startup. Three required assignments must be verified for topic completion. Specialized DSA topics with no exact Codeforces tag use a displayed broader tag, so their topic label is an approximate grouping rather than an official tag.

Roadmap reads fetch only the catalog rows referenced by that user's stored assignments. When assignments are missing, PostgreSQL ranks a bounded candidate pool inside the database before FastAPI selects stable challenges. This keeps `/roadmap/tree` responsive without transferring the entire Codeforces catalog on every page load. A missing `roadmap_challenges` table produces an explicit migration error; the frontend distinguishes that HTTP response from a timeout or an unreachable API.

The current dashboard reads `/analytics`, which aggregates saved submissions into daily, weekly, or monthly events, first accepted solves, distinct problem ratings, 365-day observed activity, topic evidence, contest rating history, and verified roadmap progress. Dates are normalized to UTC. Missing imported pages are treated as incomplete history; recommendation results are withheld when solved-status filtering cannot be trusted. Required roadmap assignments are removed from optional recommendations.

The old `roadmap_progress` table and its endpoints remain for backwards compatibility and to preserve existing user data. The current skill tree never treats a manual legacy completion as verified. `code_reviews` continues to store user-owned Gemini feedback. Historical migrations are kept intact, including retired integration tables, so existing installations can upgrade without destructive schema changes. New installations run migrations 001 through 006 in order.

Known deployment checks: apply migration 006, configure Supabase Auth and database values, verify `/health/ready`, and test an authenticated sync against the official Codeforces API. Database policies enable row-level security on user-owned tables; FastAPI uses its server-only database connection and enforces ownership before reads or writes.
